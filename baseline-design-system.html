Baseline is the agency's shared foundation. Every value below is a token — a named decision made once and reused everywhere. Designers pull them from Figma libraries; developers pull the same names from code. This page is the living spec that both sides read from.

01

Type scale

A modular scale on a 16px base. Every step has a fixed size, line-height, weight and tracking — designers don't invent sizes, they pick a role. Body faces set in Inter; a client's brand display face is swapped only at the display/h1 steps via a single token override.

Rule

Pick the role that matches the content's job, not the size you want. Need it smaller? That's a different role, not a custom size.

Never

No ad-hoc font sizes, no bold applied to body to fake a heading. Off-scale text is the first sign a project drifted.

02

Colour system

Two tiers. Primitives are the raw palette — numbered, meaningless on their own, never referenced by a component. Semantic tokens carry intent (text-primary, border-focus) and resolve to a primitive. Product code and Figma components reference the semantic layer only. This is what lets us reskin a whole client project by remapping tokens, not editing components.

Rule

Reference semantic tokens in every component. A client rebrand = remap action-primary once; every button follows.

Never

Never hard-code a hex or reference a primitive (iris-600) inside a component. Primitives change; intent shouldn't.

03

Spacing

A single 4px grid. Every gap, pad and margin is a step on this scale — enforced in Figma through Auto Layout and in code through spacing tokens. No arbitrary pixel nudging.

space-2 · 4pxicon ↔ label, tightest pairing
space-3 · 8pxinside a control (input text ↔ edge)
space-4 · 12pxbutton padding, chip padding
space-5 · 16pxcard padding, form field gap
space-7 · 24pxbetween related components
space-8 · 32pxbetween component groups
space-10 · 48pxbetween page sections
space-11 · 64pxpage-level rhythm
Rule

Spacing grows with relationship distance: 4–8 inside a component, 16–24 between components, 48+ between sections.

Never

No 5px, 15px, 22px. If a value isn't on the scale, the layout is wrong, not the scale.

04

Radius

Corner radius encodes hierarchy of surface: the larger the surface, the softer the corner. Consistency here is what makes unrelated client projects still feel like they came from the same shop.

radius-none · 0tables, data cells, full-bleed media
radius-sm · 4buttons, inputs, badges, chips
radius-md · 8menus, alerts, small cards
radius-lg · 12cards, modals, large surfaces
radius-fullavatars, pills, toggles
05

Elevation

Shadow is not decoration — it encodes how close a surface is to the user, i.e. z-order. One level per layer. Skipping levels or mixing them breaks the sense of depth.

elevation-0flush surfaces, cards on tinted bg
elevation-1resting cards, raised panels
elevation-2dropdowns, popovers, hover-lift
elevation-3modals & dialogs
elevation-4full-screen overlays, palette

This page is the living reference for Baseline v1.0.0 — the buildable spec that mirrors the Figma library structure exactly (page-per-foundation, one component per variant set). Designers consume it as a Figma team library; developers consume the same tokens from tokens.json. When the two disagree, the token file wins. See the handoff documentation for naming rules and how to read the Figma file.
